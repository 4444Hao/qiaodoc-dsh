# QiaoDoc 瘦身计划

更新日期：2026-11-02。状态：**第一轮完成；B1 示例书退出及文档入口完成，底层兼容层与 B2/B3 待后续处理**。B1 本地 87 项检查通过，桌面体验待用户验收，见 [B1 阶段记录](SLIMMING-AUDIT-B1.md)。逐文件依据、体积对照和回退范围见 [A0/A1 审计结果](SLIMMING-AUDIT-A1.md) 与 [A2 审计结果](SLIMMING-AUDIT-A2.md)。

目标：围绕“原生对话＋右侧原文＋选段交互＋粘贴保存＋文档历史”，减少无关源码、展示素材与运行时依赖，不扩大功能范围。分两轮实施：先整理仓库，再精简运行时。清理文件数和测试数量不作为成功指标。

## 必须保留的行为与数据

- 在现有会话打开工作区文件、本地文件和会话附件；右侧独立阅读，不创建另一套聊天。
- PDF、TXT、Markdown 的选段解释、翻译、复制与询问 AI；保留当前会话绑定、单次发送和草稿/附件/忙碌保护。
- 粘贴默认 TXT、可选 Markdown、可改名、UTF-8、2 MiB 上限及重名不覆盖；写入实际会话工作区，不发送消息。
- 文件历史按会话与来源路径登记，保留文档显示名称、原文位置与消息回跳。
- 保留“乔木阅读”目录、旧文件副本、历史 JSON、旧状态及浏览器存储键；不借瘦身重命名或自动迁移用户数据。
- 保留当前插件行、Remote 服务与 locale 的兼容标识，除非另有经过验证的迁移需求。
- 保留 LICENSE、适用版权、上游来源和仍适用的第三方声明；删除代码不直接等同于可删除所有相关声明。

HTML 渲染选段、未保存表单恢复、超长 TXT 精确返回等既有限制继续登记，见 [验收报告](ACCEPTANCE-REPORT.md)。本轮不增加 EPUB 原生侧栏、OCR、全文双语排版、移动端或同步能力。

## 第二轮：运行时精简

### B1：收窄当前文档数据层，移除内置书

当前 `src/client/bridge.js` 仍承担旧书库状态、缓存、内置书和多种解析职责。新入口的本地文档通过 `data.importBook()`，显示名称通过 `data.getLibrary()`，附件打开后还会 `refreshLibrary()`；不能直接删除 bridge 或把书库相关代码一概视为无用。

- [ ] 先明确当前文档操作所需的数据接口，再替换其底层实现，保持文件副本和显示名称映射兼容。
- [ ] 去掉 STARTER_BOOKS、starterCatalog、自动补入示例书和无关的内存阅读状态链路。
- [x] 确认没有执行引用后，移除 media/starter-books.js 与只服务它的生成入口；解析测试改用合成样本。
- [ ] 当前 UI 不再需要的解析和状态方法逐步退出；旧持久化文件只保留，不自动重写或清空。

验收：本地文件和附件仍可保存、打开、重载、引用和返回；旧文件副本仍能读取；客户端构建不再包含内置书内容。记录实际节省量，不以 1.13 MB 源文件大小直接推算压缩包收益。

### B2：退出旧工具、命令与 Remote 方法

朗读、Anki、找书目前仍被 Host 引用。`reader_library` 工具与 `/reader` 命令也仍注册；它们不是单纯的不可达 UI 文件。

- [ ] 对照调用图与当前产品约定，退出朗读、Anki、找书及旧阅读状态的注册和实现。
- [ ] Host 方法、`READER_REMOTE_METHODS`、客户端描述符、host-api 和测试同步调整，不能只删某一侧。
- [ ] 初步保留集合：info、library、importBook、importSessionDocument、documentHistory、recordDocumentHistory、createPastedDocument；这不是最终 API 数量承诺，按实际调用审计补足必要方法。
- [ ] 清除旧 `/reader` 文案与工具提示，明确这是旧功能退出，而不是兼容所有旧命令的无感升级。

验收：当前选段及文件操作不依赖已退出的方法。若移除旧工具影响真实模型读取当前文件或继续讨论，应先验证受支持的原生文件引用/工具路径，或暂缓该项。固定回复模型只验证传输与会话绑定，不能证明全文读取和实际回答质量。

### B3：复核解析器、资源与依赖

- [ ] 重新生成入口依赖图及输出贡献统计，确认旧 EPUB、PDF 引擎和嵌入资源是否仍被本地导入或宿主读取使用。
- [ ] 原生预览已承担的职责可逐步复用，但移除旧解析器前必须验证当前文件流程；不能因为“没有旧阅读界面”就删除所有 PDF 资源。
- [ ] 对 marked、parse5、pdfjs-dist 等逐项说明保留理由；确无源码、工具或测试用途后，再更新依赖和锁文件。
- [ ] 生成的 PDF 资源与其生成/补丁脚本成组审计，不能仅将生成文件加入忽略规则导致干净源码构建失败。

验收：无旧资源残留或悬空导入；中文 PDF、普通 PDF、TXT、Markdown 与 HTML 预览通过声明范围内的检查；从无现有依赖的源码副本执行 npm ci/check 可复现。

每阶段记录：处理文件、退出能力、源码/构建/tgz 体积对照、依赖变化、验证结果、数据兼容及遗留项。此轮不设未经验证的百分比或体积承诺。第一轮以仓库可读性为目标，第二轮要求说明实际减少了哪些加载内容；单纯改压缩选项不能冒充功能精简。

## 发布、Git 与回退边界

- 本计划不执行 Git 暂存、提交、分支、标签、PR、推送或发布；全部由维护者手动完成。
- 现有 .gitignore 已覆盖依赖、构建目录、日志、tgz、测试 profile 和用户文档。旧功能源码不靠忽略规则隐藏，Git 已跟踪文件也不会因此自动停止跟踪。
- 当前 package.files 是发布白名单；源仓库整理与缩小安装包分别核验。
- 根目录 index.js/client.js 仍作为当前预构建入口保留；除非另有经过验证的安装方式，不删除或忽略它们。
- 实施前保存可回退源码与候选；运行时变更使用新的候选版本，建议下一轮为 dev.7，不覆盖 dev.6 或旧固定标签。本轮规划不改版本号。
- 只在隔离 profile 验证；不自动安装、停用或重启日用 Harness。若之后获授权更新，需另行备份当前安装和配置，核对同包名回退；早期跨包名迁移记录不能直接当作新的回退依据。
- 任何阶段若出现当前功能回归、数据覆盖或不可解释的体积/构建变化，停止后续删除，恢复本阶段备份并重新定位。无需重写或清空用户数据来完成回退。
